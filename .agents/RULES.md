## Source-first development

- Resolve every page prompt through `.agents/skills/opx-flat-ui-development/references/page-registry.md` before choosing source. State the selected stable `PageId` during implementation. Do not treat route text, AppBar `PageTitle`, component filename, or permission key as interchangeable with `PageId`.
- Treat `samples/Opx.MudBlazor.FlatUi.Sample` as the page-development source of truth. Start from the nearest sample archetype and preserve its shell, state ownership, responsive switching, loading, modal result, toolbar, FAB, and theme behavior.
- Treat `src/Opx.MudBlazor.FlatUi` as the reusable-component source of truth. Reuse an existing component before adding page-local markup. Move a pattern into `src` only when it is genuinely domain-neutral and reusable.
- Never copy sample business wording or static records into a reusable component. Samples may demonstrate IT, ERP, ecommerce, content, and operations; shared APIs remain domain-neutral.
- Do not create a new page from memory when a matching sample exists. Read the sample and the components it invokes before editing.

## New or changed pages

- Large-record lookup forms use `FlatEntityLookup<TItem>` in the shared medium modal on desktop/wide tablet and the mandatory fullscreen modal on mobile. Keep search and result rows on one aligned edge, left-align primary/secondary item text, use dotted record separators plus a non-color-only candidate indicator, and keep one internal result-list scroller without document overflow.
- Bind `FlatEntityLookup<TItem>.Items` from `IEnumerable<TItem>` so arrays, lists, collections, observable collections, and materialized projections work without adapters. Keep remote loading, authorization, query bounds, paging, mutation notification, and API errors host-owned; do not pass a live database query to the UI.
- Set `FlatEntityLookup<TItem>.ItemKey` for API-backed or replaceable records. Use `MultiSelect`, `SelectedItems`, and checkbox rows for many-value lookup; the confirmed `ItemsSelected` result must contain canonical items from the current `Items` snapshot so stale object instances do not leak to callers.

- Register every new route with one unique `opx.page.<area>.<purpose>` ID, canonical page name, prompt cues, shell/archetype, and source file. Preserve existing IDs through display-title changes. If a component has multiple routes, register each route separately. Keep the registry, source-map, navigation/title/search entries, and audit synchronized.
- Public Job Landing pages use `WebsiteLayout` and compose search hero, process, categories, job results, employer proof, CTA, and footer. Preserve semantic headings, labeled search controls, responsive one-column mobile layout, touch targets, and no document overflow. Keep vacancy APIs, applicant identity, resume scanning, consent, workflow, analytics, notification delivery, retention, and persistence host-owned.

- Compose disclosure/FAQ/settings sections with `FlatAccordion` and `FlatAccordionItem`; preserve textual titles, full-header keyboard/touch targets, `aria-expanded`, single-open default, explicit Multiple mode, optional Flush/leading/toggle icons, disabled contrast, and Light/Dark parity. Keep loading, authorization, persistence, and content security host-owned.

- On Kanban tablet/mobile, keep only full-width search and icon actions in the toolbar; move Assignee, Priority, and other structured filters into the shared `BottomSheet` with staged Apply/Reset and discard-on-close behavior. Desktop filters remain inline.
- For catalog, product, inventory, or other filter-heavy result pages, use `FlatFilterWorkspace`: show a bounded filter rail beside the desktop result, then hide the rail at `900px` and below and expose the same staged controls through its icon-only filter `BottomSheet`. Keep status tabs and search in the result toolbar, render `FlatDataGrid` plus equivalent mobile cards from one query state, commit mobile filters only on Apply, and discard staged changes on close/backdrop/swipe. Query execution, Add/Edit, authorization, and persistence remain host-owned.
- Use `FlatProductDetail` for media-heavy product/item details and `FlatProductMetric` for summary facts. Desktop uses a gallery/summary split; tablet/mobile stacks at `900px` without document overflow. Supply gallery, thumbnails, metadata, rating, metrics, variants, description, tabs, and actions through slots. Media delivery, pricing, inventory, reviews, authorization, edit persistence, and checkout remain host-owned.
- Use `FlatEditorWorkspace` and `FlatEditorSection` for large create/edit pages. Keep main fields/gallery/inventory in the broad desktop column and publish/schedule/category/tags in the compact rail; stack both at `900px` and below without document overflow. Reuse `FlatFileUpload` and `FlatMultiSelect<T>`. Rich-text integration, sanitization, validation, media storage/scanning, scheduling, authorization, concurrency, and persistence remain host-owned.
- Compose CRM/deal pipelines from `FlatKanbanBoard<TItem>` with `FlatKanbanBoardVariant.Pipeline`, typed `ColumnHeaderTemplate`, and `FlatPipelineCard`; never duplicate movement/filter infrastructure. The host computes aggregates and owns actions, authorization, persistence, and realtime state. Desktop scrolls five-plus stages internally; tablet/mobile stack them at `900px` and below without document overflow.

- Register an exact route, route-aware `PageTitle`, sidebar item, horizontal navigation/search entry where applicable, and permission boundary owned by the host.
- Keep PageId `opx.page.reference.development-rules` at `/development-rules` synchronized with accepted repository and skill contracts so developers can inspect the current summary in the executable sample. Canonical detail remains in the source rule and skill files.
- Do not render a duplicate page title or description by default. The AppBar owns `AppName` and current `PageTitle`. At the `14.5px` baseline, keep their shared compact proportions near `11px` bold and `10px` regular; density presets must preserve those ratios.
- Use `FlatPage` for operational pages. Keep grid actions in its toolbar and hide unavailable actions. Standard writable CRUD pages define their single create action once with the `PrimaryAction*` parameters and `OnPrimaryAction`; `FlatPage` automatically produces the desktop button and icon-only mobile FAB without duplicate markup or an empty responsive action row.
- Use desktop tables above `900px` and equivalent responsive cards at `900px` and below; preserve one shared query/filter/sort/paging state. The switch must remain reversible during live window resize without reload, restore both internal table scroll axes when returning to desktop, and never create document-level horizontal overflow.
- Bind first empty requests to `FlatPage.InitialLoading`; the package chooses a responsive skeleton from `FlatPageKind`. Override with `SkeletonTemplate` or `LoadingContent` only when automatic geometry does not match, and keep global defaults in `OpxFlatUi:Loading`. Skeletons are initial-empty-state feedback only; refresh, filter, paging, sort, and CRUD reload keep current data visible and use the shared AppBar loading line.
- Desktop `FlatDataGrid` owns a single bounded two-axis scroll region. A direct `div` wrapper under `.module-panel` may use any host class; the package makes it shrinkable on desktop and hides it when the equivalent mobile grid is active. Keep toolbar and pager outside the grid scroll region, let intrinsic wide columns create horizontal overflow, let excess rows create vertical overflow, and do not add a second active scroller around the component. Use a normal-width, clearly contrasted theme-resolved thumb on both axes; a thin border-colored thumb is treated as visually missing in Dark/Night.
- For table grids, derive default filters from the grid's `GridColumnDefinition` collection. Desktop headers and `MobileGridFilterSheet` use the same `Columns` and exact `GridViewState`; toolbar Filter visibility follows `Columns.Any(column => column.FilterEnabled)`. Never create separate mobile filter metadata/state, and remove stale criteria when a column becomes unavailable.
- Grid columns support proportional `WidthPercent` and fixed `WidthPx`, with pixels taking precedence when both are supplied. Detect or declare numeric/currency columns, align their headers/cells right with tabular digits, and format through `FlatLocalizationOptions`; non-property keys use `ValueSelector`, custom templates use `FormattedValue`, and mobile cards reuse `FlatValueFormatter`.
- Mobile status cards may opt into `mobile-card-edge-tag` so the direct header chip attaches near the upper right border like a tag. Hide its decorative status bullet, keep every corner square, reserve non-overlapping title space, support short two-line status copy, preserve zero document overflow, and leave all ordinary status components unchanged.
- All shared visual components use square geometry (`border-radius: 0`) across admin, auth, website, dialog, popover, snackbar, menu, grid, toolbar, sheet, and reusable workspace surfaces. Preserve circular geometry only for semantic identity/state shapes such as avatars, radio controls, status/typing dots, circular progress/spinners, and calendar day markers. Never add page-local rounded cards or controls.
- Bind global paging defaults from typed `OpxFlatUi:Grid` appsettings and construct `GridViewState` from `FlatGridOptions` before initial loading. Keep page-specific page size and pager choices as explicit overrides. Keep the native page-size select at a one-pixel border plus one-pixel `:focus-visible` outline so keyboard focus is clear without the thicker generic ring.
- Use `FlatEditableGrid<TItem>` for inline Add/Edit/Delete. Keep one cloned draft and prefer `SaveRow` with `FlatGridEditResult<TItem>` so generated IDs/version values return as the canonical persisted row. Emit `RowResult` for every Create/Update/Delete success, failure, validation failure, and cancellation with the exact affected row. Retain failed operations in edit mode, discard Cancel without source mutation, and confirm Delete explicitly. Standard pages use `FlatPage.PrimaryAction*`; the grid Add toolbar is only for embedded grids. Switch to equivalent editor cards at `900px` and below. Authorization, collection mutation, persistence, concurrency, idempotency, and refresh remain host-owned.
- Generate ordinary flat model CRUD with `FlatModelCrud<TItem>`/`FlatModelForm<TItem>` and DataAnnotations or explicit typed field metadata. Use `FlatModelFieldKind.SearchComboBox` plus local `Options` or cancellable `SearchOptionsAsync` for lookup fields, and per-field `EditorTemplate` for any other visual component. Keep host ownership of authorization, API persistence/search bounds, canonical results, business validation, collection reload/mutation, confirmation, concurrency, and audit. On standard pages hide the component Add action and route `FlatPage` Add/FAB to `BeginCreateAsync`; only embedded CRUD may show local Add. Cancel leaves source/caller state unchanged; successful mutations emit `RowResult` and `Changed`.
- For a modal lookup inside Auto CRUD, declare a `Custom` field and render `FlatEntityLookup<TLookup>` through the shared `FieldTemplate`. Use stable lookup keys, support checkbox multi-select when required, map selected records to model keys in host code, and call the template context's `NotifyChanged` after mutation.
- A modal opened inside another editor uses form-less nested content and topmost-only history interception. Closing or pressing Back on the lookup must close only that lookup, never submit/cancel the parent form or discard its draft.
- Build visual generated-form layout with `FlatModelFormDesigner<TItem>` and PageId `opx.page.reference.model-form-designer`. Preserve drag/drop and Move up/down parity, one/two-column preview, stable field keys, validated class tokens, bounded `0..48px` spacing, Light/Dark parity, and a one-column mobile designer without page overflow. Native fields, searchable combos, image fields, and per-field custom visual editors must all retain the same layout wrapper and live-preview behavior. Feed the normalized layout to `FlatModelForm.Layout`/`FlatModelCrud.FormLayout`; host code owns authorization, class allowlists, persistence, versioning, concurrency, and audit. Keep wrapper emphasis transparent and limited to a restrained rail/keyline so it never replaces an input, combo, custom editor, or textarea theme surface.
- Auto CRUD text, numeric, date, select, and multiline editors default to one outlined floating label derived from metadata `Label`/`Display(Name)`. Keep `Placeholder`/`Display(Prompt)` as the optional hint inside the control, keep the required marker in the floating caption, and retain an inline label for checkboxes. The label background must compute to transparent in every theme; use only a two-pixel surface-matched pseudo-element to mask the outline behind the caption. Match shared responsive/high-density typography; do not render a duplicate external label, rectangular label block, or second focus ring.
- Apply Auto CRUD numeric `DisplayFormat`/field `Format` to desktop grid, mobile cards, and the generated editor. Resolve culture from registered `FlatLocalizationOptions` (`OpxFlatUi:Localization:Culture`) and use `CurrentCulture` only as the missing-registration fallback. Return the original numeric property type, retain `inputmode="decimal"`, and keep native `type="number"` only when no format is configured.
- Align inline Boolean checkboxes in two-column Auto CRUD forms to the adjacent outlined control center-line with the same 4px top rhythm. Preserve the established 38px control height and intrinsic grid row height.
- Keep 16px mobile outer gutters. Use no-FAB bottom 16px or safe-area-aware FAB clearance as defined in root `RULES.md`.
- In phone Bottom navigation, the hidden hamburger must not collapse AppBar content against the viewport; keep the AppBar toolbar at `16px` left/right gutters while preserving the standard 64px header rhythm.
- Use `FlatFormModal`/`CrudEditorShell` for CRUD editors. Mobile editors are fullscreen; cancel/back returns false without refresh, while successful CRUD submit may refresh through the caller pipeline.
- Enable pull-to-refresh only on eligible pages with a real handler. Reuse the shared native-like resistant gesture, pull/release/refresh indicator, held refresh position, and snap-back; do not build page-local variants. Browser simulation is not native MAUI proof.
- Keep Light, Dark/Night, Auto, palette, density, font, disabled state, portal, snackbar, reconnect, and backdrop behavior synchronized with shared settings. Dark component surfaces must use the shared graphite hierarchy and must not reintroduce legacy pure-black component islands. Hosts using `Auto` load the OPX theme bootstrap in `<head>` before stylesheets so first paint already matches the device and remains subscribed to later system-theme changes.
- Keep the built-in `blue` palette's enabled Filled Primary surface at reference `#004a77` in Light and Dark/Night, with white content and palette-derived hover/subtle/emphasis states. Change it through typed host palette configuration, never a page-local button selector.
- Use `14.5px` as the OPX base-font baseline through `OpxFlatUi:Display:DefaultFontSizePx`; retain host bounds and persisted user overrides until Restore application defaults clears them.
- Scale all shell, navigation, page, grid, dialog, menu, Settings, and reusable-component text from `--opx-ui-font-size`. Keep icons and density-owned spacing/control geometry independent so Font size never changes the selected spacing preset.
- At the `14.5px` baseline, calibrate information-dense Comfortable-style screens to approximately `13px` operational text, `12px` supporting text, and `11px` metadata through shared ratios. `Compact`, `Default`, and `Comfortable` may change control height and spacing, but must not silently change those font ratios or the persisted font-size preference.
- Keep first-paint root classes (`opx-root-theme-light`/`opx-root-theme-dark`) separate from component shell classes (`theme-light`/`theme-dark`). Auto follows the device as one coherent resolved theme; explicit Light or Dark overrides the device for root background, shell, cards, controls, and portals together.
- Keep default enabled checkboxes accent-colored when checked/indeterminate, readable when unchecked, and paired with normal foreground labels. Disabled checkbox glyphs and labels use a clearly quieter neutral in both themes; checkbox icon surfaces remain transparent/shadowless and explicit semantic checkbox colors remain intact.
- Configure sidebar menu Light/Dark background and foreground through typed `OpxFlatUi:Display` options and shared shell variables. Validate six-digit hex input, retain safe defaults, and preserve semantic hover/active contrast.
- Keep the sidebar search placeholder compact and regular (`9-10px`, weight `400`) through a selector scoped to `.sidebar-search-input`; do not let the larger form-placeholder rule enlarge or bold it.
- Keep native placeholders, empty/non-floating labels, floating labels, entered textbox/textarea values, and selected combo values at normal `400` weight. Preserve their responsive size, color, dense height, gap, outline, and label geometry.
- Treat AppBar global search as one composite control. Keep exactly one visible focus indicator on `.global-search`; its inner native input remains transparent and must not draw an independent focus-visible outline or box-shadow. Shared outlined MudBlazor fields use a one-pixel softened-Primary border, no fieldset shadow, and no second native-input outline while preserving established floating-label color and geometry. Verify both patterns in Light and Dark/Night.
- Make each outlined field container own one continuous theme-resolved background across the value and adornment areas, including autofill. Keep adornment wrappers, glyphs, and icon buttons transparent, borderless, and shadowless over that surface; ordinary icon buttons retain their component-specific surfaces and interaction states.
- Apply `opx-password-visibility-field` to Login/auth password controls with show/hide. Keep the visibility icon white in resolved Dark/Night and `#212529` in resolved Light regardless of the current password/text input type; retain a transparent icon surface and accessible toggle semantics.
- Keep browser-autofilled inputs, textareas, and selects on the same resolved field surface, foreground, and caret colors as ordinary values in Light, Dark/Night, and Auto. Enforce both standard `:autofill` and Chromium `:-webkit-autofill` globally for hover/focus/active states; do not patch Login alone or let autofill create a separate block beside an adornment. Preserve field geometry, labels, outlines, and disabled behavior.
- Treat application metadata and authentication branding as mandatory initial host setup. Before implementing feature pages, bind typed `OpxFlatUi:Application` options and seed appsettings with `AppName`, `CompanyName`, `Author` (default `opx`), copyright, `LoginBrandBackgroundColor`, `LoginBrandBackgroundImageUrl`, `LoginBrandOverlayColor`, and `LoginBrandOverlayOpacity`. Render the resolved author once in the host document `<head>` as `<meta name="author">`; it applies to every route and must not be duplicated page by page. Keep `Logo` and `LogoUrl` optional: when neither resolves, omit every logo wrapper and its spacing; when configured, validate the URL and keep the mark compact. Render the validated brand-panel color/image/overlay from host configuration. Use the operational split desktop/mobile Login pattern, omit the duplicate top mobile identity row, and disable inputs during a single-flight submit. Do not inject raw CSS from configuration or copy the reference application's API/session contracts into the reusable sample.
- Do not add a static security/integration or `Sample only` banner below Login. Route required-field and invalid-credential feedback through `FlatMessageBoxService.ErrorAsync` using generic wording. Keep sample credentials explicit and local-only; the host owns real authentication/session behavior.
- Give Not Found content standard page gutters and resolve unknown routes to the AppBar PageTitle `Not found`.
- Derive nested sidebar typography and geometry from tree depth rather than expanded/collapse transition classes. Font size, icon size, row height, and text position must remain identical before and after first click.
- Use `FlatNavigationBadge` for compact sidebar counts/statuses on leaf links or `MudNavGroup.TitleContent`. Preserve the group's plain `Title` for `aria-label`; dot-only badges require a meaningful `AccessibleLabel`. Badge appearance must follow semantic Light/Dark tokens and may not shift sidebar icon/text/connector/chevron geometry.
- Use `FlatDynamicMenu` for flat-record autoload navigation with `MenuText`, `Id`, `ParentId`, `Url`, and `Icon`. Validate duplicate/missing IDs, labels, unknown/self parents, and cycles; recursively preserve search and active-route expansion. Convert the same tree through `FlatDynamicMenuBuilder.ToNavigationItems` for horizontal and Bottom layouts. Keep API authentication, authorization filtering, tenancy, ordering, localization, caching, retries, and route permission enforcement host-owned; hidden menu items are not authorization.
- Scope Email sender-copy selectors to `.flat-email-sender-copy`; never let a broad direct-`span` rule override the span root of `FlatProfileAvatar`. Verify initials remain centered and fully visible at desktop/mobile widths. Email-list sender, subject, and preview copy must always begin on the same full-width track; unread state, timestamp width, attachment, and star metadata must not center or shift a row independently. Preserve at least `14px` between copy and the row edge and `6px` after the star action so unread markers, selected rails, and actions stay clear of the border.
- AI chat pages compose the shared Chat shell/components and keep prompts, history, model/provider, streaming, persistence, and authorization host-owned. Use a bounded desktop history/thread split and separate mobile history/thread states at `900px` and below; Back returns to history. Keep sending single-flight with responding/Stop states and clearly identify static responses as local simulation. Never expose provider keys or privileged tokens in Razor, browser storage, query strings, logs, or client configuration.

## Roadmap components

- For 1.2-1.5 enterprise work, read `EnterpriseToolkit.razor` and `docs/ENTERPRISE-TOOLKIT.md`; preserve typed host callbacks and never embed domain persistence, authorization, parsing, workflow engines, sync transport, or document storage in reusable UI.
- Keep Enterprise component roots and showroom headers on the shared font family with compact `calc(var(--opx-ui-font-size) * .82759)` normal-weight copy. Use `.68966` for supporting text and semibold only for headings or meaningful emphasis.
- Resolve ERP application-building requests to PageId `opx.page.erp.toolkit` and start from `ErpToolkit.razor`. Reuse typed transaction, entity lookup, money/quantity, journal, reconciliation, planning, lifecycle, and background-operation components. Keep posting/accounting, tax, UOM, inventory traceability, matching, scheduling constraints, authorization, concurrency, durable jobs, audit, and persistence in the host.
- Master-detail becomes mobile list/detail without browser history. Scheduler and Calendar overflow remains internal; `FlatCalendar` keeps Year as a responsive 3/2/1-column twelve-month grid and switches Month/Week/Day/List to a grouped agenda at `<=900px`, retaining host-owned typed event/day/date/view callbacks. Audit hides sensitive values unless explicitly enabled. Offline Sync and Documents are presentation adapters only.

- Tree Grid hierarchy is host-owned: use typed key/parent selectors, reject cycles, return old/new parent keys from move callbacks, and provide touch-accessible promote/indent actions in addition to Web drag/drop.
- Mobile Tree Grid uses a Windows Explorer-style continuous list with folder/file icons, chevrons, bounded indentation, dotted branch connectors, secondary metadata, pressed feedback, and a three-dot action menu. It must not reuse desktop columns, drag affordances, or large standalone cards.

- Run unit, bUnit, public API, responsive Playwright, and axe gates before accepting additive public APIs.
- Keep `FlatFileUpload` transport/storage/security and native picker adapters host-owned.
- Use `FlatImageUpload` for multiple images with responsive previews and exact original/output metadata. Default to 70% proportional autoscale only above a 2560px long edge, never upscale, and cap output at 3200px; expose overrides through `FlatImageUploadOptions`. The host/backend must independently validate bytes and dimensions, decode/re-encode, handle metadata, scan, authorize, store, and return canonical media results.
- In generated model forms, image fields are explicit: use `FlatModelFieldKind.ImageUpload` plus the typed `FieldTemplate`; never infer them from string/byte-array properties. Call `FlatModelFieldTemplateContext.NotifyChanged` after successful draft mutation so dirty-state remains truthful.
- Keep report query, authorization, subtotal business rules, PDF/Excel generation, scheduling, storage, and delivery host-owned. `FlatOperationalReportViewer<TItem>` owns only responsive presentation and interaction callbacks.
- Build pivot pages with `FlatPivotGrid<TItem>` and typed row/column/value selectors. Keep aggregation scope explicit, return exact source items on cell selection, use one internal desktop matrix scroller, and switch to equivalent cards at `900px` and below. Keep desktop analysis controls inline inside an `8px 10px` padded panel; controls use zero outer margin and an `8px` gap so outlined fields never touch the panel border. Place multiple tablet/mobile Pivot controls in the shared filter `BottomSheet` behind one icon-only result-header button; stage state on open, commit it atomically on Apply, and discard pending state on close. Derive matrix and card typography from compact `--opx-ui-font-size` ratios, and reduce those ratios again at the phone breakpoint instead of inheriting full body text or using fixed pixels. Server aggregation, authorization, units, export, persistence, and OLAP remain host-owned.
- Keep saved grid views scoped per user through `IFlatGridPreferenceProvider`; normalize state by schema and load virtual windows through cancellation-aware host callbacks.
- At `700px` and below, Grid Preferences uses explicit mobile grid areas: visibility/label/order on row one and width/pin on row two. Target the actual MudBlazor wrapper classes, normalize dense margins, and prevent implicit placement from creating tall or misaligned records.
- Keep wide showcase controls contained within their panel with internal overflow instead of cross-card overlap.

## Configuration and state

- Put reusable defaults in typed options bound from `OpxFlatUi` appsettings sections. Normalize unsafe or out-of-range values in the library.
- Keep `opx-flat-ui.js` canonical and readable. Generate, never hand-edit, `opx-flat-ui.min.js` during Release/Pack with the pinned build-time toolchain. Debug loads source; Release resolves source/minified through typed `OpxFlatUi:Assets` settings, defaulting to minified. Validate both assets inside the NuGet package.
- Keep user-specific preferences/session state scoped. Never use static/singleton mutable state shared between users.
- Keep sample data explicitly static/in-memory unless a real integration is implemented and verified.
- Preserve query state during refresh. Do not hard-reload a page after a successful CRUD operation; use the existing load pipeline.

## Roadmap and compatibility

- Follow `ROADMAP.md` and the current `2.0.x` source line. The 1.6-2.0 surfaces are accessibility/quality, command palette, advanced schema form, collaboration/conflict UI, and operational compositions.
- Protect additive 2.0 APIs with unit/bUnit, responsive Light/Dark/Auto/reduced-motion Playwright, axe, public API compatibility, Windows/Linux CI, package inspection, fresh-consumer restore, and migration documentation.
- Treat a local package as evidence for that exact run, not proof that the release gate is complete. Roadmap documentation never authorizes package publication.
- Keep server aggregation/export, file parsing/import/storage/security, per-user saved views, Master–Detail data, audit records, localization resources, realtime transport, lock leasing, comments, conflict persistence, business workflow/mutation, and timezone/business formatting host-owned through explicit contracts.

## Application experience 2.0

- PageId `opx.page.reference.experience-toolkit` is the source for accessibility, command palette, advanced schema form, collaboration, and conflict requests. PageId `opx.page.operations.workspace` is the source for Service Desk, Approval Inbox, Procurement, Stock Transfer, Timesheet, and POS/Cart compositions.
- `FlatCommandPalette` owns keyboard search/navigation and exact selection callbacks only. Hosts authorize and execute routes/actions.
- `FlatSchemaForm` keeps one value state across conditional fields and steps; computed values run before change/autosave callbacks, cross-field issues identify field keys, and draft autosave is cancellation-aware.
- `FlatCollaborationPanel` and `FlatConflictResolver` present host state and return typed intent. They do not imply a live SignalR/WebSocket transport, durable comments, lock enforcement, merge, or audit.
- Require visible focus, reduced-motion, forced-colors, direction, axe, and responsive checks. Native MAUI accessibility/device claims require matching emulator/device evidence.
- For Experience/showroom compositions, use the shared `panel-header` structure and preserve visible section separation: 12-14px between release/summary strips and content, 14px panel gaps on desktop, 12px on mobile, and 14px/12px panel-body padding. Do not compensate by changing global density or the 16px mobile page gutter.

For every accepted reusable change, update together:

- root `RULES.md`;
- relevant `docs`/`README.md`;
- `.agents` rules, source map, or local skill when the development contract changes;
