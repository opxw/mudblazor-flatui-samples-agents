# OPX Flat UI development

Use the repository's compiled sample as the behavioral source of truth and the RCL source as the reusable API source of truth. Do not introduce another UI framework.

## Start every task

1. Read repository `RULES.md` and `.agents/RULES.md` completely.
2. Read [page-registry.md](references/page-registry.md), resolve the prompt to one canonical `PageId`, then read [sample-source-map.md](references/sample-source-map.md) and select its closest archetype.
3. Open that sample page/layout and every shared component it directly uses.
4. Inspect nearby repository instructions and the current worktree before editing.
5. State the selected `PageId`; state any assumption that materially changes page type, permissions, data ownership, or responsive behavior.

## Roadmap gate

- Read repository `ROADMAP.md` before work that changes tests, uploads, grid preferences, virtualization, public APIs, versions, or packaging.
- Follow the approved order: finish the `1.1.0` release-hardening gate, then Advanced Pivot, Data Import Wizard, Master–Detail, Audit Trail, and Localization for `1.2.0`.
- Do not introduce `1.2.0` public APIs before unit/bUnit, responsive and Light/Dark/Auto Playwright, accessibility, public API compatibility, Windows/Linux CI, package inspection, fresh-consumer restore, and migration documentation protect current behavior.
- Treat a local `1.1.0` package as evidence for that exact run, not proof that hardening is complete. Do not bump or publish merely because roadmap documentation changed.
- Keep server aggregation/export, file parsing/import/storage/security, per-user persistence, Master–Detail data, audit records, resources, and timezone/business formatting host-owned through explicit interfaces/callbacks.

## Choose the implementation surface

- For dynamic/autoload navigation records shaped as `MenuText`, `Id`, `ParentId`, `Url`, and `Icon`, select PageId `opx.page.reference.dynamic-menu`, use `FlatDynamicMenu`, and reuse `FlatDynamicMenuBuilder.ToNavigationItems` for horizontal/Bottom navigation. Keep arbitrary-depth hierarchy validation/presentation in the library, while endpoint authentication, authorization filtering, tenancy, ordering, localization, caching, retries, and route permission enforcement remain host-owned. Never treat menu visibility as authorization.
- For ERP transaction documents, large entity lookup, money/quantity/UOM, journal balance, reconciliation, planning, lifecycle, or background-operation UI, select PageId `opx.page.erp.toolkit` and compose the shared ERP components from `ErpToolkit.razor`. Keep fiscal periods, posting, tax/discount, UOM conversion, stock/lot/serial traceability, matching authority, capacity rules, durable jobs, authorization, audit, concurrency, and persistence host-owned.
- Render `FlatEntityLookup<TItem>` in the shared medium modal on desktop/wide tablet and the mandatory fullscreen modal on mobile. Keep the search and option list aligned, option copy left-aligned and truncation-safe, records separated with dotted lines, the candidate identified by color plus a check glyph, and the result list as the only internal scroller.
- Bind lookup `Items` as `IEnumerable<TItem>` so host arrays, lists, `ICollection<T>`, observable collections, and materialized projections are accepted directly. Keep remote loading, authorization, query limits, paging, collection change notification, and API failures in the host; never send an unbounded/live database query into the component.
- Set lookup `ItemKey` whenever API refreshes may replace object instances. For checkbox lookup use `MultiSelect`, bind `SelectedItems`, and consume `ItemsSelected` as the exact confirmed list canonicalized against the current `Items` snapshot. Empty selection is a valid clear result; business-required validation remains host-owned.

- Compose public career portals under `WebsiteLayout`, with search hero, process, categories, jobs, employers, and CTA. Do not reuse the admin shell or claim live recruiting integrations; host owns vacancies, candidates, resumes, consent, workflow, and delivery.

- Use `FlatAccordion`/`FlatAccordionItem` for reusable disclosure groups. Preserve textual accessible titles and full-header interaction when icons are hidden; default to one open item and opt into Multiple or Flush deliberately.

- Add page composition and domain examples under `samples/Opx.MudBlazor.FlatUi.Sample`.
- Add or change `src/Opx.MudBlazor.FlatUi` only for domain-neutral reusable behavior.
- Extend an existing shared component before duplicating its markup in several pages.
- Keep services, authorization, persistence, API clients, and native platform adapters owned by the host through explicit interfaces/callbacks.
- Treat `wwwroot/opx-flat-ui.js` as the only JavaScript source to edit. Release/Pack generates `opx-flat-ui.min.js` through the pinned repository toolchain. Bind `FlatAssetOptions`; Debug must select source and Release defaults to minified while allowing an explicit appsettings override.

## Build a page from a sample

1. Copy the structural pattern, not the sample's business text or records.
2. Preserve the registry's stable `PageId`, or allocate a unique `opx.page.<area>.<purpose>` ID for a new concept and register its canonical name, route, cues, shell/archetype, and source in `page-registry.md`.
3. Add an exact `@page` route and update route-aware AppBar title/search/navigation sources.
4. Keep operational pages free of duplicate title/description blocks unless explicitly requested. Preserve the shared AppBar AppName/PageTitle proportions near `11px`/`10px` at the `14.5px` baseline, with bold/regular hierarchy unchanged by density presets.
5. Use `FlatPage`, shared toolbar actions, desktop table, responsive cards, shared pager/query state, and the correct FAB/no-FAB contract.
6. Use shared modal, processing, message-box, settings, notification, and reconnect components instead of page-local alternatives.
7. Keep all field controls dense and theme synchronized; include disabled, loading, empty, error, and narrow viewport states. Make an outlined field container own one continuous theme-resolved surface across its value and adornment areas, including autofill; keep adornment wrappers, glyphs, and icon buttons transparent, borderless, and shadowless over that shared surface without changing unrelated icon buttons. On focus, use one softened-Primary one-pixel outlined border with no fieldset shadow or second native-input outline, while preserving established floating-label color and geometry.
8. Establish application metadata and Login branding during initial host scaffolding, before feature-page development. Bind typed `OpxFlatUi:Application` options and seed `AppName`, `CompanyName`, `Author` (default `opx`), copyright, `LoginBrandBackgroundColor`, `LoginBrandBackgroundImageUrl`, `LoginBrandOverlayColor`, and `LoginBrandOverlayOpacity` in appsettings. Render `ApplicationOptions.ResolvedAuthor` once as `<meta name="author">` in the host document `<head>` so every route inherits it; do not repeat metadata in individual pages. Treat both `Logo` and `LogoUrl` as optional; omit the logo wrapper and reserved gap when neither resolves, and keep a configured logo compact. Validate colors and opacity in the library, allow only relative/HTTP(S) image URLs, and render images as `<img>` instead of raw configured CSS. Follow the operational split desktop/mobile composition, omit the duplicate top identity row, lock fields during a single-flight submit, omit static security/sample banners below the form, and show required/invalid credential feedback through the shared Error MessageBox with generic wording. Do not import or imply the reference application's live auth/session contract.
9. Give Not Found content standard page gutters and map unknown routes to the AppBar PageTitle `Not found`.
10. Mark Login/auth password controls with a show/hide action using `opx-password-visibility-field`; keep the eye icon white in resolved Dark/Night and `#212529` in resolved Light regardless of whether the input currently renders as password or text.
11. Preserve English reusable/sample defaults and copyright headers.

## CRUD and data rules

- Configure the standard CRUD create action once through `FlatPage.PrimaryActionVisible`, `PrimaryActionLabel`, `PrimaryActionIcon`, `PrimaryActionAriaLabel`, and `OnPrimaryAction`. Let `FlatPage` render the Filled desktop button above `900px` and the icon-only FAB at `900px` and below; do not pair the automatic API with manual `HeaderActions` or `MobilePrimaryAction` markup.
- Keep filter/search/sort/paging state shared between desktop and mobile views. Table-grid filters default to the `GridColumnDefinition` contract: pass the same `Columns` collection and exact `GridViewState` to `FlatDataGrid` and `MobileGridFilterSheet`, and derive toolbar Filter visibility from whether any column has `FilterEnabled=true`. Do not duplicate mobile filter metadata/state; clear stale criteria when columns are disabled or removed.
- Size reusable data-grid columns with `WidthPercent` for proportional layouts or `WidthPx` for fixed geometry; pixels win when both are set. Let `FlatDataGrid` infer numeric public properties or declare `ValueKind`/`Format`, use `ValueSelector` for non-property keys, and consume `FlatGridCellContext.FormattedValue` in custom cells. Numeric headers/cells stay right-aligned with tabular digits and use registered `FlatLocalizationOptions`; equivalent mobile cards reuse `FlatValueFormatter`.
- For an edge-attached mobile status label, add the opt-in `mobile-card-edge-tag` modifier to `mobile-card` and keep the status chip as the direct header child. Place it near the upper header edge, hide its decorative bullet, and preserve reserved title space, compact two-line wrapping, square corners, exact right-border attachment, and zero document overflow; never change all status components globally.
- Enforce the package-wide square geometry contract: cards, panels, controls, buttons, dialogs, popovers, snackbars, menus, grids, toolbars, sheets, and reusable workspaces use `border-radius: 0` in every shell. Restore circular geometry only for semantic identity/state shapes (avatars, radio controls, status/typing dots, circular progress/spinners, and calendar day markers), and reject page-local rounded overrides.
- When an accepted UI or development contract changes, keep the executable `/development-rules` sample summary synchronized with the canonical rules, this skill, page registry, and source map.
- Bind reusable paging defaults from `OpxFlatUi:Grid` into `FlatGridOptions`, register the options with the host, and initialize each page's `GridViewState` from them before the first local/API load. Preserve `SetPageSize(...)` and `FlatPager.PageSizes` for intentional page-specific overrides. Keep the native page-size select at a one-pixel border plus one-pixel `:focus-visible` outline so keyboard focus is clear but not visually heavy.
- Hide Filter when no actionable filter UI exists. Keep import/export/download/refresh/custom actions icon-only in one toolbar row.
- Keep one scroll owner per desktop grid: `FlatDataGrid` provides the bounded vertical/horizontal region, while toolbar and pager stay fixed. A custom direct `div` host under `.module-panel` is supported without a package-specific class name; it must resolve shrinkable on desktop and disappear when the equivalent mobile grid is active. Do not add a competing active wrapper scroller; verify `scrollHeight > clientHeight` and `scrollWidth > clientWidth` cases with `overflow:auto` and visible theme-synchronized scrollbars, including while a modal locks document scrolling. Use normal scrollbar width and a clearly contrasted theme-resolved thumb on both axes; do not use a thin border-colored thumb that appears absent in Dark/Night. Repeat that verification after a no-reload desktop -> tablet/mobile -> desktop resize cycle and after changing viewport height.
- Bind each `FlatPage` initial empty request to `InitialLoading`. Let `FlatPageKind` choose the default skeleton (`Module` grid, `CrudForm`/`Settings` form, `Dashboard` dashboard, other kinds list/detail); use `SkeletonTemplate`, count overrides, or `LoadingContent` only when automatic geometry needs refinement. Global defaults come from `OpxFlatUi:Loading`, while `SkeletonEnabled` is the page-level opt-out. On later refresh, filter, sort, paging, or CRUD reload, retain existing content and use the AppBar loading line; never reuse the initial-loading flag for those operations.
- Return modal result false for Back, Cancel, or permitted backdrop close without caller refresh. Return true only after successful submit; refresh CRUD callers through their existing query-preserving load pipeline.
- Make mobile CRUD editors fullscreen and safe-area/keyboard aware. Consume system/browser Back in the editor before page navigation.
- Make API loading single-flight, cancellation-aware where supported, and truthful about failures. Never present HTTP 200 alone as business success when the host contract has its own result/status envelope.
- Build inline row Add/Edit/Delete with `FlatEditableGrid<TItem>`: one cloned draft, host-owned cancellable persistence, validation that retains the draft, Cancel without source mutation, and explicit destructive confirmation. Prefer `SaveRow` returning `FlatGridEditResult<TItem>` for the canonical persisted row and consume `RowResult` for exact per-row Create/Update/Delete success, failure, validation, and cancellation outcomes. Use the page primary action for standard Add/FAB behavior and grid Add only when embedded. Supply equivalent mobile templates.
- For a prompt requesting automatic list/grid/forms from a model, select PageId `opx.page.reference.model-crud` and compose `FlatModelCrud<TItem>` with `FlatModelForm<TItem>`. Use DataAnnotations for defaults and typed `FlatModelFieldDefinition<TItem>` overrides for non-trivial fields. Use `FlatModelFieldKind.SearchComboBox` with local `Options` or cancellable `SearchOptionsAsync` for lookups; use per-field `EditorTemplate` when a visual control needs its own strongly typed composition. Keep persistence, authorization, API search bounds, canonical results, business validation, confirmation, collection reload, concurrency, and audit in the host. Standard pages hide embedded Add and delegate `FlatPage` Add/FAB to `BeginCreateAsync`; Cancel must not mutate/reload, while successful mutations emit `RowResult` and `Changed`.
- For modal lookup fields in generated forms, declare explicit `FlatModelFieldKind.Custom` definitions and render `FlatEntityLookup<TLookup>` from the shared `FieldTemplate`. Set stable lookup keys, use checkbox `MultiSelect` where appropriate, map selected records to model key properties in host callbacks, and call `NotifyChanged` after mutation. Keep the lookup dataset and persistence host-owned.
- Keep nested lookup modal content form-less and make modal history interception topmost-only. Closing or using browser/system Back on the child lookup must preserve the parent CRUD editor and draft.
- For a visual generated-form/WYSIWYG layout prompt, select PageId `opx.page.reference.model-form-designer` and compose `FlatModelFormDesigner<TItem>`. Preserve stable model keys, drag/drop plus accessible Move up/down, field visibility/span, validated class tokens, bounded `0..48px` spacing, and exact `FlatModelForm` desktop/mobile preview. Ensure native fields, `SearchComboBox`, image upload, and per-field custom visual editors all use the same layout wrapper and preview contract. Return normalized `FlatModelFormLayoutDefinition` through `LayoutChanged` and reuse it through `FlatModelForm.Layout` or `FlatModelCrud.FormLayout`. Never accept raw CSS/HTML/script; class allowlists, authorization, per-user/tenant persistence, versioning, concurrency, and audit remain host-owned. Demonstrate emphasis with a restrained rail/keyline on a transparent wrapper; never use a saturated full-wrapper fill that makes the generated control look nested or mixed-theme.
- Default generated Auto CRUD text, number, date, select, and multiline fields to one outlined floating label from metadata `Label`/`Display(Name)`. Preserve `Placeholder`/`Display(Prompt)` as an optional inner hint, float the required marker with the caption, and keep checkbox labels inline. Keep the label background computed transparent in every theme and use only a two-pixel surface-matched pseudo-element to mask the outline behind the caption. Reuse shared responsive/high-density typography, compact gaps, and one focus indicator; do not add page-local label CSS.
- Reuse numeric `DisplayFormat` or explicit field `Format` across generated grid/card output and the Auto CRUD editor. Resolve culture from the host-registered `FlatLocalizationOptions` (`OpxFlatUi:Localization:Culture`), with `CurrentCulture` only as fallback when options are unavailable. Formatted editor text carries a decimal numeric keyboard hint and parses back to the property's original numeric type; keep native number input behavior when no format is configured.
- In generated two-column forms, give inline Boolean checkboxes the same 4px top rhythm as adjacent outlined controls so both center-lines match. Keep the 38px control height and intrinsic row sizing unchanged.

## Responsive and theme rules

- Keep Kanban structured filters inline only above `900px`. At tablet/mobile widths, leave search full-width in the toolbar and open Assignee, Priority, or equivalent filters through one icon-only Filter action into the shared `BottomSheet`; stage values, apply atomically, and discard them on close/backdrop/swipe.
- Compose filter-heavy management pages with `FlatFilterWorkspace`. Use its left rail on desktop, staged `MobileFilterContent` in the shared sheet at/below `900px`, `ResultToolbar` for status tabs and full-width mobile search, and `ChildContent` for one `FlatDataGrid`/`FlatMobileGrid`/`FlatPager` query state. `OnReset` clears the staged sheet values, `OnApply` commits them atomically, `OnDismiss` restores committed values, and `OnClear` clears committed filters. Keep API loading, row actions, authorization, and persistence in the host.
- Compose product/item detail pages with `FlatProductDetail` and summary facts with `FlatProductMetric`. Fill explicit slots for media, thumbnails, metadata, rating, metrics, variants, description, detail tabs, and actions. Keep the two-column desktop split and one-column `<=900px` layout, preserve 16px mobile gutters and no document overflow, and keep image transport, pricing, stock, reviews, authorization, checkout, and edit persistence host-owned.
- Compose large create/edit pages with `FlatEditorWorkspace` and `FlatEditorSection`: main content/gallery/inventory in the broad desktop region, publish/schedule/category/tags in the settings rail, and one source-ordered column at/below `900px`. Reuse `FlatFileUpload` and `FlatMultiSelect<T>`. Treat rich text as optional host integration and keep sanitization, validation, media storage/scanning, scheduling, authorization, concurrency, save, and cancel host-owned.
- Build CRM/deal pipelines as the `FlatKanbanBoard<TItem>` Pipeline variant with a typed column-header template and `FlatPipelineCard`; do not create a second movement/filter implementation. Let the host calculate totals and own actions/persistence. Keep five-plus desktop stages inside the board's own horizontal scroller and stack them at `900px` and below without page overflow.

- Enable pull-to-refresh only on eligible pages with a real handler. Reuse `FlatPage`'s shared native-like vertical direction lock, resistant finger-following indicator, pull/release/refresh states, held refresh position, and snap-back. Do not duplicate the gesture or indicator in a page. Browser simulation is not native MAUI proof.
- Use `14.5px` as the configured OPX base-font baseline for new hosts; keep it bounded and overridable through `OpxFlatUi:Display:DefaultFontSizePx`.
- Drive every textual surface from `--opx-ui-font-size`, preserving each component's ratio to the `14.5px` baseline. Do not scale icons, spacing, or control geometry when Font size changes; those remain owned by the selected density preset.
- Use the shared Comfortable-style hierarchy at the `14.5px` baseline: about `13px` for operational text, `12px` for supporting text, and `11px` for metadata. Density presets alter rhythm and touch geometry only; never couple a density change to a different font-size preference.
- Preserve equal 16px mobile outer gutters and viewport/AppBar/safe-area-aware panel height.
- In phone Bottom navigation, keep the hamburger absent and apply `16px` left/right AppBar toolbar gutters; do not let AppName/PageTitle or trailing actions inherit the compact drawer-mode edge spacing.
- Switch operational tables to equivalent cards at 900px and below; desktop tables start above 900px. Keep the transition reversible during live resize, preserve one query state, and do not use page-level horizontal scrolling as the mobile solution.
- Keep Light and Dark/Night surfaces, portals, selection, placeholder/floating-label typography, disabled states, snackbars, backdrops, and reconnect UI on shared tokens/options. Dark administrative components use the shared graphite hierarchy (`#1a1d21`, `#212529`, `#262a2f`, `#2a2d31`, `#292e32`, `#32383e`) and must not retain legacy pure-black islands. For `Auto`, verify the host loads `opx-flat-ui-theme-bootstrap.js` before stylesheets, first paint matches `prefers-color-scheme`, and later device-theme changes update the active shell without reload.
- Keep default checkbox state explicit: checked/indeterminate uses the active accent, unchecked remains readable, enabled labels use normal foreground, and disabled glyph/label contrast is substantially quieter in both themes. Keep checkbox icon surfaces transparent and do not override explicit semantic checkbox colors.
- Preserve `#004a77` as the built-in `blue` palette's enabled Filled Primary surface in both Light and Dark/Night, with white content and the documented hover/subtle/emphasis family. Apply primary changes through `FlatUiColorPaletteOption` and shared tokens, not page-local button CSS; appsettings may intentionally replace the built-in palette.
- Verify theme resolution as one atomic state: root uses isolated `opx-root-theme-*` first-paint classes, the active shell uses `theme-*`, and explicit Light/Dark must override a conflicting device preference without mixed root/card/control surfaces. Never reuse the shell `theme-dark` class on `<html>`.
- Expose sidebar menu background and foreground as validated six-digit Light/Dark host options under `OpxFlatUi:Display`; pass normalized values to `FlatAppShell` CSS variables and preserve semantic hover/active contrast.
- Add sidebar status/counts with `FlatNavigationBadge`. Place it in a leaf link's child content or a parent group's `TitleContent`, while keeping the parent `Title` populated for accessibility. Use a meaningful `AccessibleLabel` for dot-only badges and verify that badge presence does not shift the established icon, text, connector, or chevron coordinates across expand/active/responsive states.
- Keep nested sidebar font/icon/row/padding selectors depth-based and independent from transient expand classes. Verify the first expand/collapse click does not change computed typography or text coordinates.
- Treat the sidebar search placeholder as compact navigation copy: approximately `9-10px`, weight `400`, scoped to `.sidebar-search-input` so global form and AppBar placeholder typography is unaffected.
- Keep native placeholders, empty/non-floating labels, floating labels, entered text, and selected combo values at normal `400` weight without changing responsive size, color, dense height, gap, outline, or label geometry.
- Keep browser autofill theme-synchronized globally: standard `:autofill` and Chromium `:-webkit-autofill` hover/focus/active states must retain the resolved field surface, foreground, and caret colors without splitting the input area from its adornment. Do not change control geometry or scope the correction only to Login.
- When a layout contains `FlatProfileAvatar`, target adjacent copy through an explicit class rather than a broad direct-`span` selector. Preserve the avatar root's `display:grid`, fixed geometry, clipping, and centered initials/image; verify narrow and desktop rendering. Email list rows keep one stable copy track with at least `14px` edge clearance and `6px` after the star action; unread dots and selected rails stay inside that gutter.
- Treat browser breakpoint tests as Web proof only. Require emulator/device validation for MAUI system Back, IME, safe areas, lifecycle, permissions, notifications, and native gestures.
